# What would make Restore better?

These are contribution priorities, not delivery dates or claims of completed support. The established Studio chain stays the default until a replacement demonstrates preservation and cleanup on varied vocals.

| Priority | Why it matters | Evidence needed before calling it done |
| --- | --- | --- |
| Commercially permitted model path | Both profiles currently depend on a non-commercial aspiration model; denoise terms also need clarification. | Checkpoint-specific rights/provenance, and comparisons on held-out singing, chants and speech. |
| Easier Windows installation | The current release is source-only and needs several dependencies. | A fresh-machine setup run, explicit model/license handling and tested recovery from missing prerequisites. |
| Reproducible public listening examples | Current real recordings are private; numerical tests cannot establish perceptual quality. | Recordings with explicit publication rights, matched before/after boundaries and levels, config/version/hardware/timing records, and honest failure examples. No private recordings in source commits. |
| Lightweight click repair with stronger evidence | AudioJS is fast but is not proven equivalent to the Studio default. | Labelled click regions plus consonant/sustain preservation, blinded controls and compute measurements. |
| macOS and Linux verification | Upstream libraries supporting an OS does not prove the complete Restore app works there. | Full install, file handling, cancellation, native hosting and end-to-end listening checks on each claimed platform. |

Useful smaller contributions include keyboard/accessibility improvements, clearer setup errors and reproducible synthetic fixtures. Read [Contributing](../CONTRIBUTING.md) before changing audio behavior. No cloud service, account system or timeline editor is needed to address these priorities.
